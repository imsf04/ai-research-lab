04 · AI Research Lab

The agent loop is an explicit state machine

Plan → Retrieve → Analyze → Critique → Publish

Conditional transitions

  • Critic identifies evidence gaps → plan another search
  • No new evidence → stop further retrieval
  • Valid findings and completed review → publish
  • Tool or model failure → retain a qualified partial report

Host-enforced controls

  • Keep the research goal and open questions in state
  • Correct the actual query when planning drifts
  • Deduplicate evidence and retain source IDs
  • Limit calls, rounds, excerpts and elapsed time
Loop state = plan + sources + queries + findings + issues + outcome
Snapshot   = state + next node + budget counters + elapsed time
Current limits: 5 retrieval rounds · 28 model calls · 40 excerpts · 3.2M reservation units, not a currency cap
Explain why explicit state and conditional edges are useful: the system can pause, inspect, resume and test each transition.

Retrieval combines local context and external sources

Local knowledge

  • Ingest Markdown or text into overlapping chunks
  • Store vectors and source metadata with pgvector
  • Hybrid search combines dense similarity and BM25 through reciprocal rank fusion
  • Read trusted documents through MCP when appropriate

External evidence

  • Brave Search returns web excerpts and URLs
  • Keep the retrieved text for citation checks
  • Associate evidence with the task-local source index
  • Report retrieval degradation and missing evidence
query → retrieve candidates → filter / rank → deduplicate → assign source IDs
      → draft → structured findings → verify quoted text → review

Model and embedding providers are configurable. Web search requires a separate Brave API key.

Distinguish the hybrid knowledge-base interface from the graph’s selected retrieval path: not every research step invokes every retrieval strategy. Web results are excerpts, not guaranteed full-paper access.
06 · AI Research Lab

Approval is a durable execution boundary

AI Research Lab · Editable search approval

Inspect the goal, the question served and the editable query before retrieval.

Pause, persist, resume

  • Save the plan and next node before pausing
  • Approve the original query or edit it
  • Resume without repeating planning
  • Require fresh approval before a local-search fallback uses MCP
  • Use leases to prevent concurrent execution
Planning itself may already use the model. Approval gates the proposed retrieval, not all previous computation. If a crash leaves an external call uncertain, the system interrupts conservatively rather than claiming exactly-once recovery.

08 · AI Research Lab

Validate the boundaries that matter

Behavior covered by tests

  • Edited queries reach the retriever
  • Source quotations resolve to retrieved text
  • MCP fallback waits for approval
  • Rejected plans do not read documents
  • Continuation preserves instructions and uses the latest gaps

Failure handling

  • No relevant evidence: preserve unresolved questions
  • Invalid quotations: retry within limits or mark the report unverified
  • Provider errors: expose a useful failure state
  • Interrupted external calls: avoid uncertain replay

Integration approach

Web, CLI and backend integrate through task, approval, event and evidence contracts. Snapshot-based fixtures test handover between execution segments; isolated PostgreSQL tests cover persistence and concurrent decisions.

Separate deterministic regression coverage from research quality. These tests demonstrate execution behavior; they do not measure scientific correctness or search completeness.
